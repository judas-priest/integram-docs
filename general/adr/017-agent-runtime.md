# ADR-017: Рантайм агента Integram — заземлённое действие по правилам с правом отказа

**Статус:** proposed

## Контекст

Integram хранит данные клиента и даёт агенту ~307 инструментов. Возник вопрос: что есть
главный навык агента — «писать запросы»? Реверс выигрышных архитектур индустриальной арены
ИИ-агентов **BitGN ECOM1** (агента судит прогон в мире-двойнике бизнеса) дал чёткий ответ:
**нет.** Запрос — это доступ (низший слой). Балл (и доверие клиента) дают:
- заземление каждого ответа на конкретную запись (winner B: +22пп одной правкой grounding);
- применение регламента (политики — источник истины, цитируются);
- авторизация и **отказ** (проверка прав до действия; отказ от небезопасного/неоднозначного;
  устойчивость к инъекциям);
- восстановление после сбоев (incident recovery — транзиентные ошибки ретраить, не сдаваться).

Integram — EAV, не чистая SQL-база. Значит агент должен работать не сырым SQL, а через
**объектный слой** (Client/Order/Product, ADR-016), где у каждого объекта есть стабильный путь.

## Решение: рантайм агента = конвейер из 5 уровней

Каждое обращение агента к данным клиента проходит:

```
1. ДОСТАТЬ   объект через объектный слой (не EAV-строки) — с его record_path
2. ЗАЗЕМЛИТЬ ответ на реальные записи (object-grounding): нет ссылки → не считается
3. РЕГЛАМЕНТ найти применимую политику/решение и ПРИМЕНИТЬ; процитировать её как ref
4. ОТКАЗ     проверить право (identity/role + row-permissions) ДО чувствительного действия;
             отказать при: нет прав | чужие данные | инъекция/давление | НЕОДНОЗНАЧНОСТЬ (переспросить, перечислив кандидатов)
5. АКТ       мутировать только при праве, перепроверить успех; записать необратимый акт с автором в W
```

Запрос живёт на уровне 1. Навык агента — вся петля, и особенно **уровень 4 (отказ)**:
для клиентских данных «скорее отказать, чем солгать» — это и есть доверие.

## Что менять в Integram (от существующего)

| Уровень | Что уже есть | Что достроить |
|---|---|---|
| 1 Доступ | EAV, `query`/`semantic_search`/`graph_query`, объектный слой #37/#47 | объектный слой как ОСНОВНОЙ интерфейс агента к данным; запрос всегда возвращает record_path |
| 2 Заземление | — | `object-grounding` (PR #48): ответ/сопоставление только с точным record_path; в эффектор как обязательный гейт |
| 3 Регламент | `_v2_decisions`, KAG | политики/правила как **цитируемый источник**: агент применяет и ссылается на запись политики |
| 4 Отказ/авторизация | RBAC, row-permissions, контур безопасности #19–21, HITL | проверка прав ДО чувствительного действия; явные исходы отказа (нет прав / чужое / инъекция / неоднозначность); DLP-контур |
| 5 Акт | W-матрица, audit-log, эффектор | каждый ответ/мутация — необратимый акт с автором и ссылкой на запись; перепроверка после мутации |
| (надёжность) | BullMQ, retry в задачах | детерминированный ретрай транзиентных сбоев инструментов (incident recovery) |

## Что это значит для Мета-КБ

Мета-КБ **и есть** этот рантайм: среда, где агент действует на бизнес-объектах клиента,
заземлённо, по правилам, с правом отказа, под полный аудит. Арена подтвердила тезис Мета-КБ:
ценность не в «умной модели», а в **объектном слое + регламенте + заземлении + отказе + следе**.
Позиционирование: «агент, который действует на ваших бизнес-объектах, заземлён в реальных
записях, по вашим правилам, отказывает в недопустимом — с полным журналом». Это ровно то,
что арена награждает баллами, а предприятие — доверием к данным клиента.

## Последствия

- Приоритет разработки агента смещается с «оптимизировать запросы» на **объектный слой +
  заземление + авторизация/отказ**. Запрос — необходимое, не достаточное.
- Каждый клиентский ответ агента становится прослеживаемым актом — основа доверия и аудита.
- Агент по умолчанию **read-and-decide**; мутация — редкое, авторизованное, проверенное действие.

Связано: ADR-016 (объектный слой), PR #48 (object-grounding), эпик #28 (ревью-ворота),
issues #19–21 (контур безопасности). Источник уроков: реверс архитектур BitGN ECOM1.
