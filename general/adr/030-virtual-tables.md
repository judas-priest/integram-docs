# ADR 030: Виртуальные таблицы (типы без строк в EAV)

## Статус
Принято (2026-09-14)

## Контекст
Состав участников воркспейса живёт в сателлитных таблицах `_v2_users`/`_v2_memberships`
и невидим для системы таблиц: на него нельзя смотреть как на таблицу, фильтровать,
сортировать. Материализация в EAV («завести таблицу и синкать строки») ломает
инвариант `objectWhere()` (shared/sql-guards.js), плодит рассинхрон и вторую копию истины.

## Решение
Паттерн «виртуальный тип» по образцу виртуального отчёта 9001 (report-engine.js):

1. Тип существует ТОЛЬКО как код: константа ID и карта колонок в одном модуле
   (`api/v2/utils/virtual-types.js`). Первый обитатель — 9002 «Участники».
2. Никаких строк типа в `"db"."db"` и `_v2_type_meta`.
3. Чтение — своя ветка в `listObjects`/`getObject`, отдающая контрактную форму
   ответа objects; в `getAllTypes`/`getType` — синтетическая схема с флагом `isVirtual`.
4. Запись запрещена guard'ом `assertNotVirtualWrite` во ВСЕХ пишущих точках
   обоих путей (REST service.js и AI tools/objects.js), включая trash-restore,
   rollback (оба — REST и AI), CSV-import, `moveChildren`, automations
   (`create_object` в execution.js, `upsertRequisite` в lifecycle.js — fieldId 9002
   без colDef отвергается; легитимный colDef-коллизионный id пишет штатно).
5. Доступ на чтение — членство воркспейса (middleware), не гранты EAV.

## Известные допущения
- **Коллизия id**: если в воркспейсе реальная EAV-таблица получила id 9002
  (последовательность общая с объектами), список отдаст реальную таблицу
  (инъекция пропускается), но `getType(9002)`/чтение строк уводят в виртуальный
  источник — реальная недостижима. То же допущение, с которым годами живёт
  грант-отчёт 9001. Сайдбар фильтрует 9002 из дерева безусловно.
- Владелец без строки членства появляется в таблице только после первого
  открытия страницы участников (ensure живёт в workspace-members.js; GET-путь
  objects сознательно без side-effects).
- Доступ «любой член воркспейса» вместо грантов — чтение участников не сильнее
  страницы настроек, где тот же список видит любой member.

## Последствия
+ Единый источник истины: состав участников меняется только приглашениями.
+ Новый виртуальный тип = константы + ветка чтения + guard'ы, по чек-листу ADR.
− Виртуальный тип нельзя подчинить записи (вкладка в карточке — вне скоупа).
  Ссылка на участника реализована типом колонки «Пользователь» (COLLABORATOR 1010,
  план 2026-09-14-user-column-1010.md): хранит _v2_users.id, валидируется членством,
  в отчётах резолвится в имя, фильтры поддерживают [USER_ID].
  Известное ограничение: CSV-импорт канонизирует только числовые значения 1010.
  Замер прода 14.09.2026 (128 воркспейсов): таблиц с id 9002 нет ни в одной
  (строки id=9002 в 19 воркспейсах — значения колонок, не типы); колонок/значений
  типа 1010 — ноль во всех. Поле чистое, коллизий нет.
**Аменд 17.09.2026 (план 2026-09-17-pm-issues-as-ref-directory.md):** ограничение
«виртуальный тип нельзя ссылаться ref-колонкой» снято для read-only виртуальных
типов с полной веткой ref-поддержки. Первый ref-таргет — 9003 «Задачи»
(`_v2_pm_issues`). Ветка обязана покрывать ВСЕ точки ref-механики: опции
(`getLookup` + `getRefReqs` — формы, ячейки, `/refs`, MCP `get_ref_options`),
резолв «id → имя» в `listObjects` (REST) и `loadObjectValues` (AI-путь, правило
dual paths), `resolveRefColumns` отчётов. Запись по-прежнему запрещена
(`assertNotVirtualWrite`). Известные допущения расширяются: сортировка по
такой ref-колонке и текстовый фильтр по имени — не поддерживаются (работает
фильтр по id из опций); затенение id-пространств — то же, что у 9002.

− getObject несёт префикс-lookup (один индексный запрос) на каждом чтении.
− Новые пишущие пути (как automations execution/lifecycle, найденные при ревью)
  обязаны добавлять guard — структурный страж `virtual-write-guards.test.js`
  не знает о файлах, которых не было на момент его создания.
