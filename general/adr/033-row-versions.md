# ADR-033: Версионность строки с подчинёнными таблицами (В1/В2 как коммиты)

**Статус:** accepted

## Контекст

Кейс финмодели (PM-310, «Инструмент Ульянова» в fund_demo): строка-расчёт с
подчинёнными таблицами правится агентом, нужна история как в git — В1, В2, В3…,
переключение между версиями целиком (строка + ВСЁ её поддерево). Существующие
механизмы не годятся: schema-snapshots — структура без восстановления,
data-snapshots — страховочный блоб всей таблицы с чисткой через 30 дней,
audit-log/rollback — по-полевая история ОДНОЙ строки без подчинённых.

## Решение

Новая сателлитная таблица `_v2_row_versions` (по воркспейсу, `wsTable`): снимок
JSONB «области версии» — строки, её ячеек и рекурсивного поддерева (дети, внуки,
их ячейки) — одним рекурсивным CTE, как в корзине (`trash.js`). Автополя
(IMMUTABLE_CTYPES) в снимок не входят, восстанавливаются `writeAutofields`.

- Создание версии — явно: `POST /objects/:id/versions`; необязательные
  value/requisites применяются ПЕРЕД снимком — правка строки = новая версия,
  а не перезапись ячеек. Обычный PATCH остаётся перезаписью: автоснимок каждой
  правки по всей платформе раздувает таблицу, а правило «мастер-версию правит
  только Ульянов» уже сдерживает записи процедурно.
- Переключение = восстановление в живые строки (стирание области + вставка
  снимка с новыми id, родители раньше детей). Живые строки после переключения
  ЕСТЬ версия — все существующие читатели (список, отчёты, sandbox query)
  показывают её без единой правки. Текущее состояние перед реальным
  переключением автосохраняется как версия.
- Один активный указатель на строку (`is_active`, частичный уникальный индекс).
- Версии умирают со строкой (`bus.on('object.deleted')`).
- Хранение: последние 100 версий на строку, активная не чистится.

## Последствия

- Нельзя жить версиями-копиями ВНУТРИ EAV: они попали бы в каждый список,
  счётчик детей, отчёт и sandbox query, а «переключение фильтром» заставило бы
  править десятки читателей. Снимок + восстановление оставляет читателей
  нетронутыми.
- Ссылки на записи ВНУТРИ области версии висят после переключения (val не
  перемапливается). Ссылки наружу — целы; финмодель ссылается на размерности
  и счета наружу. Принято как ограничение.
- Восстановление из корзины поднимает строку, но не её версии.
- Diff, merge, блокировки — вне скоупа; конфликт правок решён правилом
  «мастер-версия принадлежит Ульянову», платформенного замка нет (YAGNI).
