# ADR-036: Событийные процессы как модуль платформы (валидация спек при записи + State Transition Operation)

Статус: предложен (2026-09-27). Контекст: аудит «Событийного рабочего стола» fund-demo (issue #253), документы #21/#24/#33/#35/#37, бенчмарк Boldsea/BSL (PM-146, док #32).

## 1. Аудит системы (текущее состояние)

Спеки фонда существуют в **трёх несвязанных слоях**, каждый со своим хранилищем, движком и валидацией:

| Слой | Хранилище | Движок | Валидация |
|---|---|---|---|
| Процессные спеки («как жизнь течёт») | EAV-таблица 8593 | events-desktop.vue (fund-app, клиент), agent-worker.mjs (fund, сервер), таймеры воркера | мета-валидатор R1–R6 — только на клиенте (вкладка «Спеки процессов»); на сервере — ничего |
| Спеки-проверки регламента («соответствует ли жизнь норме») | 2062/2063 | спек-раннер run-fund-demo-specs.mjs (fund, сервер) | реакция BLOCK/WARN/DEFER, сторож нашёл живые нарушения |
| Спеки ИСТОК (исполняемые контракты «конструктор→исполнитель») | серверная таблица «Спека ИСТОК (портал)» | istok-engine.vue (fund-app): генерация агентом из решения, 4 уровня валидации × 2 оси | уровни 1–2 клиентские правила, 3–4 — агент |

**Дефекты, найденные аудитом 27.09 (слой 1):** запись события — голый `POST /objects`, сервер не проверяет ничего; в журнале 8657 (1673 записи) живой дубль несмежной записи; в спеке 185 событий — 19 без ключей (недостижимы для движка), 14 висячих ссылок «Следующие», 4 оборванные цепочки, процесс без достижимого терминала, исхода «отказ» нет ни в одном из 44 процессов.

**Теоретическая рамка (guru-уровень индустрии):** State Transition Operation (microservice-api-patterns) — легальность перехода проверяет сервер; relaxed soundness (Aalst; Dehnert/Rittgen) — клиент-only допустим («ответственный пользователь»), но только при спеке, где у каждого события существует корректный путь; статические проверки спеки (deadlock/unreachable/terminal) делаются при сохранении определения, а не в рантайме (школа WF-net, BPMN Analyzer 2.0).

**Вывод аудита:** клиент-only (relaxed soundness) — легитимный выбор, но текущая спека ему не удовлетворяет; и платформа уже владеет всеми нужными паттернами по отдельности (ИСТОК: «ошибки умирают при записи»; раннер: BLOCK/WARN; мета-валидатор: R1–R6) — они не соединены и не серверные.

## 2. Решение

Завести модуль платформы **`workflows`** («Событийные процессы»), обобщающий слой процессных спек:

1. **Спека как типированный CRUD с валидацией при записи** (перенос мета-валидатора на сервер): ключ обязателен и уникален; `Следующие` — только существующие ключи того же процесса; ровно один старт; от старта достижим терминал; события без исходящих ссылок — явные терминалы. Нарушение = отказ записи с перечнем дефектов (паттерн ИСТОК: «ошибки умирают при записи»).
2. **State Transition Operation**: `POST /:db/workflows/:process/events {object, key, fields, cause?}` — сервер вычисляет состояние объекта из журнала, проверяет смежность, gate (requires), роль, «не терминал», пишет append-only запись журнала с provenance атомарно. Единственный канал записи для человека, агента и таймера (док #21: «по одним правилам»).
3. **Журнал** — таблица модуля (append-only, `cause` структурным ref с обходом ловушки self-ref, см. §4), API чтения состояния и биографии. Паттерн event store: события неизменяемы, поправка — компенсирующее событие; `seq` в потоке (процесс, объект) с `UNIQUE` и запретом UPDATE/DELETE на уровне БД; **оптимистичная конкуренция** (expectedSeq) — ровно она исключает дубль несмежной записи, найденный аудитом; снапшоты не вводим до доказанной нужды.
4. **Таймеры** (`days:N;after:spawn:`) — платформенный cron модуля с дедупом (правило «повторный прогон не создаёт дублей»).
5. **Роли** — справочник платформы вместо ROLE_MAP внутри events-desktop.vue (док сам просит перенести).

## 3. Не делаем

- Не трогаем слой 2 (раннер регламента) и ИСТОК — они отдельные слои по доку #21; модуль не конкурирует с ними.
- Не мигрируем fund-demo силами модуля: воркспейс переезжает отдельной задачей после приёмки модуля (данные спеки 8593 переносятся как есть).
- Не строим LLM-генератор спек (это ИСТОК/Boldsea, PM-146).

## 4. Ловушки, учтённые дизайном

- self-ref ref-колонка журнала (8657→8657) молча отбрасывается портальным POST и падает на update — в модуле причина хранится структурной колонкой собственной таблицы (не через портал), JSON-дубль `__cause` не нужен.
- append-only журнала: исправления — новые записи (док #35), удаления нет, trash не подключается.
- идемпотентность таймеров и повторных прогонов — сверкой последнего `after`.

## 5. Альтернативы

- **Оставить как есть (клиент-only)** — отвергнуто: спека не удовлетворяет даже relaxed soundness, дефекты накапливаются молча; починка данных лечит следствие, не причину.
- **Только сторож-валидатор в fund-demo (автоматизация на 8593)** — отвергнуто: воспроизводит прикладной обходной код, который PLATFORM_LEVEL_FLEXIBILITY запрещает; не даёт State Transition Operation.

## 6. Этапы

1. Починка данных спеки fund-demo (19 ключей, 14 ссылок, 4 обрыва, терминал комплаенса) — независимо от модуля.
2. Модуль: спека + валидация при записи + журнал + State Transition Operation (REST+MCP двойные пути, тесты, доки по README модулей). — этап 2 исполнен 28.09, ветка feat/workflows-eav-integration.
3. Таймеры и роли.
4. Переезд fund-demo на модуль; Рабочий стол остаётся UI, запись — только через модуль.
5. Синхронизация с PM-238 (разбор спек Алексеем — «ничего не удалять») и PM-146 (Boldsea-стенд: критерий приёмки «рантайм допускает только поведение модели»).

## Имена и ключи (07.10.2026)

Имя процесса: `^[a-z0-9][a-z0-9_-]{0,199}$` (lowercase kebab, `_` — по канону
SLUG_RE воркспейсов). Ключ события и set_by: `^[A-Za-z0-9._-]{1,200}$` —
точка легальна (канон `a.start`); запрещены разделители синтаксиса: запятая
(csv next_keys/resets/when_cond), `;` и `:` (parseTimers), пробелы. Единое
объявление — `workflows/names.js`; границы: Zod-regex в router.js (REST, 400),
гварды assertProcessName/assertEventKey в service.js (MCP/AI-путь, 422
SPEC_INVALID), правило KEY_CHARSET в validateSpec. Audit 07.10.2026: 0 имён
вне charset по всем схемам прода — введено без миграций; тестовые литералы
старого канона (`ИК`, `P2`) приведены к charset (`ik`, `p2`) — правились
данные тестов, не assertions.
