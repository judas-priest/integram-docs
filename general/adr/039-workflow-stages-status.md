# ADR-039: Этапы и статус в workflows — enter-переходы, s304, фильтр чужого этапа

Дата: 2026-09-30. Статус: принято. Наследник ADR-037/038.

## Контекст

Правило 5 процесса v2 фонда (PR #275): событие, переводящее объект на другой
этап, выставляет статус 304 этого этапа; статус может меняться и внутри этапа
(доработка после ИК-1 ставит 679, созыв ИК-1 возвращает 678); незавершённые
необязательные события прежнего этапа при переходе снимаются. Правило 3:
событие доступно, когда его этап совпадает с этапом объекта либо событие
стоит вне этапов.

Индустриальный референс — CMMN: stage как фаза кейса с критериями входа/выхода;
снятие активностей чужой фазы — exit-семантика. Наш движок проще CMMN: этапы
линейно-переходные, вход — явный `enter` события.

## Решение

1. **Колонки спеки.** `stage` — этап события; `enter` — этап, на который
   событие переводит объект; `s304` — значение статуса, которое событие
   выставляет. Всё необязательное: событие без `stage` стоит вне этапов и
   доступно всегда (по фронту), событие без `enter` этап не меняет.
2. **Реестр этапов** `_v2_workflow_stages (process, id, s304, days)` — по
   образцу реестра условий (ADR-037): валидатор R12 сверяет `stage`/`enter`
   событий с реестром и согласованность `enter`→`s304`. `days` хранится для
   будущего контроля срока этапа, движком в этом объёме не используется.
3. **Реплей этапа и статуса.** `stageState(specByKey, stream, superseded)`:
   по свежим (не сброшенным, ADR-038) событиям — последний `enter` задаёт
   этап; до первого `enter` этапом становится `stage` стартового события;
   последний непустой `s304` — статус. Между возвратом круга и перезаписью
   статус держится последнего свежего носителя.
4. **Фильтр чужого этапа.** `availability()` получает текущий этап: событие
   с `stage`, не совпадающим с текущим, — inapplicable (не существует для
   объекта сейчас; на записи — 422 «неприменимо», на чтении — исключается из
   available). Это и есть «снятие необязательных событий прежнего этапа».
5. **Статус наружу.** `getState` возвращает `stage` и `status`. Движок НЕ
   пишет EAV-колонку объекта — значение отдаётся решившим (стол/звавший);
   никаких захардкоженных reqId.
6. **Таймеры.** Токен `stage:X` в колонке `timer`: cron не взводит
   порождение, если текущий этап объекта не `X` (правило 9 — таймер гаснет
   при уходе из этапа; круг уже гасил его в ADR-038).

## Последствия

- Спеки без `stage`/`enter`/`s304` не меняют поведение ни на йоту (этап null,
  фильтр выключен, status в state = null).
- Валидатор R12: `STAGE_UNKNOWN`, `ENTER_UNKNOWN`, `ENTER_STATUS_MISMATCH`.
- Per-outcome статусы (fx.s304 у исходов ИК) — не входят; статус задаётся
  событием целиком. Следующий слой при необходимости.
