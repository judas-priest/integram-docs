# Финмодель: матричные отчёты (план/факт)

Матричный вид превращает плоский отчёт в таблицу «статьи × месяцы». Типичное
применение — финансовая модель: план по статьям бюджета против факта по
транзакциям. Живой пример — воркспейс `ariadna-fin`, отчёт «ОПиУ Сводный».

Адрес экрана: `/{воркспейс}/reports/{id}/matrix`, либо кнопка матрицы из
табличного вида отчёта.

## Что нужно от отчёта

Матрица строится не из любой таблицы, а из **отчёта** (Отчёты → создать), в
котором есть:

- минимум **две колонки группировки** (например «Статья» и «Месяц»);
- минимум **одна агрегатная колонка** с функцией **SUM** (AVG/COUNT тоже
  подходят) — например «Сумма план».

Отчёт без агрегатной колонки матрицу не построит — экран скажет об этом
прямо.

## Оси: строки, столбцы, значение

Три оси задаются адресом страницы или панелью «Настройка осей»:

| параметр URL | смысл | пример из финмодели |
| --- | --- | --- |
| `rowCol` | строки | «Статья» |
| `colCol` | столбцы | «Месяц» |
| `valCol` | значение (агрегат) | «Сумма план» |

В параметрах допустимы оба вида имён — и чистые («Статья»), и внутренние с
кодировкой EAV (`:ALIAS=Статья::!NULL:`); при смене осей через панель в адрес
записываются чистые имена. Номера месяцев 1–12 рисуются названиями
(«Январь»…«Декабрь»).

## Режим план/факт

Добавьте к адресу `factReportId={id второго отчёта}` — матрица загрузит факт
и покажет в каждой ячейке три числа:

```
   17 812 487   ← план (мелким, серым)
   11 600 000   ← факт (жирным)
   -6 212 487   ← отклонение: факт − план, с процентом
```

Правила сопоставления факта с планом:

- колонки факта ищутся **по именам колонок плана**: строка и столбец — по
  совпадению имени («Статья», «Месяц»), значение — агрегатная колонка факта
  (у неё может быть другое имя: «Сумма» против «Сумма план»);
- месяц факта может быть числом или формулой над датой (`EXTRACT(MONTH …)`)
  — значения выравниваются;
- строка, встречающаяся **только в факте**, показывается отдельной строкой:
  план — прочерк, факт — его суммы;
- если в факт-отчёте не нашлось колонки с именем оси плана, факт не
  подмешивается — матрица показывает один план.

**Чтобы дельта считалась построчно, статьи факта должны называться так же,
как статьи плана.** Расхождение имён («Воронки» против «Точка жизни») не
ошибка — обе строки показятся, но дельта сведётся только в итоге.

## Прочерк и ноль — разные вещи

- `—` — данных нет: пары «строка × столбец» не существует ни в плане, ни в
  факте. Отклонение в такой ячейке тоже прочерк.
- `0` — измеренный ноль: запись существует, сумма равна нулю.

Итого считается только по известным значениям: ячейка «нет данных» не
превращает итог в ноль.

## Редактирование ячеек

Работает в режиме **без** факта (одна величина на ячейку). Двойной клик —
правка, `Enter` — сохранить, `Esc` — отмена.

- очистить ячейку и сохранить — **удалить запись**;
- ввести `0` — записать измеренный ноль (запись не удаляется);
- созданию записи помогает столбец-ссылка строк: строка, найденная по имени,
  пишется ссылкой.

## История ячейки

Правый клик по ячейке открывает историю значений: когда, кем, было → стало.
История ведётся платформой автоматически для каждой записи; стирание ячейки и
создание заново начинают новую цепочку. Кнопки отката в диалоге нет — откат
всей записи доступен в карточке записи (История → Откат).

## Строки-формулы

К адресу добавляется `formulas` — JSON-массив виртуальных строк:

```
?formulas=[{"label":"Прибыль","formula":"[Доход]-[Расход]-[НДС]"}]
```

- в квадратных скобках — имена строк матрицы;
- формулы — только `+ - * /` и скобки, без `eval`;
- ссылка на отсутствующую строку делает ячейку прочерком (подстановка нуля
  запрещена — иначе формула молча выдаёт ложный результат);
- деление на ноль и нечислимая формула дают прочерк, а не ноль — ноль в
  финансовом отчёте был бы ложным утверждением;
- строки-формулы подсвечены и считаются по столбцам и в «Итого».

## Если матрица пустая или сломанная

1. **Пустая решётка из прочерков.** Оси не совпали с колонками отчёта —
   откройте «Настройка осей» и выберите колонки вручную.
2. **«Отчёт должен содержать минимум 2 колонки группировки…»** — в отчёте
   нет агрегатной колонки или второй группировки.
3. **Ошибка вместо таблицы.** Отчёт не смог выполниться (битое значение в
   колонке, отказ базы). Экран показывает ошибку — это намеренно: отчёты не
   маскируют отказ исполнения под «нет данных». Причина обычно в данных:
   например, в поле-дате лежит число эпохи вместо даты — чинится правкой
   значения в таблице-источнике.
4. **Факт весь в прочерках, план живой.** В факт-отчёте нет колонок с именами
   осей плана, либо его строки не прошли сопоставление — сверьте имена
   колонок в конструкторе обоих отчётов.
5. **Предупреждение «Факт не подмешан».** В факт-отчёте нет колонок с именами
   осей плана — матрица показывает один план. Переименуйте колонки в
   факт-отчёте так, чтобы строка и столбец совпадали с планом.
6. **Предупреждение «Показаны первые N строк из M».** Данных больше потолка
   выборки (10 000 строк) — часть ячеек отсутствует. Добавьте фильтры в отчёт
   (например, по году), чтобы уложиться в потолок.

## Версии модели (В1/В2): версии как измерение

Вместо снапшотов всей таблицы версия заводится как обычная колонка-справочник:

1. В таблице модели (и в её подчинённых таблицах, если значения хранятся
   построчно) создайте ref-колонку «Версия» на справочник «Версии»
   (записи: В1, В2, В3…).
2. Создайте по отчёту на версию (или один отчёт с колонкой «Версия» и
   фильтром) и откройте матрицу с `factReportId` второй версии — получите
   сравнение В1 ↔ В2 в режиме план/факт.
3. Правило «мастер-версию меняет только владелец» закрывается построчными
   правилами доступа на таблицу (строка В1 — только владельцу на запись).

История предыдущих значений внутри версии не теряется — она видна правым
кликом по ячейке (см. «История ячейки»).
