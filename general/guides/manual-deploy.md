# Выкладка руками

`scripts/deploy-prod.sh` покрывает обычный случай. Этот документ — для случаев,
когда он не подходит: сервер устроен не так, как ожидает скрипт; нужно выложить то,
о чём скрипт не знает; выкладка отказала на середине; надо откатиться.

Порядок установки с нуля — в [`docs/deploy.md`](../deploy.md). Здесь не он.

---

## Прежде чем что-либо делать

Три вопроса, на которые надо ответить ДО первой команды. Пропуск любого из них уже
приводил к порче.

**1. На какую машину я смотрю и один ли на ней стенд?**

```bash
pm2 status
ls -1 /etc/nginx/sites-enabled/
```

Машина может быть не выделенной. Рядом бывают: второй стенд той же платформы
(процессы с суффиксом `-dev`, свой каталог, своя база), вспомогательные службы и
вовсе посторонние проекты. Всё, что живёт не в каталоге установки прода, — чужое.

Отсюда: **`pm2 restart all` запрещён.** Перезапускать поимённо.

**2. Не отстаёт ли моё рабочее дерево?**

```bash
git log --oneline -1
node scripts/check-prod-drift.mjs --host <адрес>
```

Выкладка из устаревшего дерева молча возвращает прод назад: `rsync` синхронизирует
каталог целиком, и у кого дерево старше, тот и откатит чужую правку. Так уже
случалось — заслон ролей был открыт обратно и это заметили через полтора суток.

**3. Кто ещё сейчас выкладывает?**

```bash
ssh <адрес> 'tail -20 /opt/integram/.deploy-journal.log'
```

Журнал пишет каждая выкладка: время, машина, путь рабочего дерева, коммит, исход.
Строка «начало» без «готово» означает прерванную выкладку — разбираться, а не
накладывать поверх.

## Ручная выкладка бэкенда

Скрипт делает то же самое, но без него — так:

```bash
# 1. Обязательные ключи .env на сервере (без них процесс поднимется и не соединится)
ssh <адрес> "grep -oE '^[A-Za-z_][A-Za-z0-9_]*=' /opt/integram/backend/.env | tr -d ="  \
  | sort -u > /tmp/have.txt
grep -vE '^[[:space:]]*(#|$)' scripts/deploy-required-env.txt | sort -u > /tmp/need.txt
comm -23 /tmp/need.txt /tmp/have.txt   # пусто = всё на месте

# 2. Код. БЕЗ --delete: на сервере есть то, чего нет в дереве
rsync -az -e ssh backend/src/     <адрес>:/opt/integram/backend/src/
rsync -az -e ssh backend/scripts/ <адрес>:/opt/integram/backend/scripts/

# 3. Перезапуск ТОЛЬКО своих процессов
ssh <адрес> 'pm2 restart integram worker'

# 4. Слепок для ежедневной сверки — снимается ПОСЛЕ, «вот это мы признали»
node scripts/check-prod-drift.mjs --host <адрес> --record
```

**Почему без `--delete`.** На сервере рядом с кодом лежит то, что живёт только там:
артефакты, репозитории кодспейса, копии. `--delete` их сносит. Уже сносил — дважды.

## Ручная выкладка фронта

Фронт собирается локально и уезжает как статика. Единственное место, где `--delete`
уместен, — и именно поэтому опасен.

```bash
cd frontend && npx vite build && cd ..

# СНАЧАЛА вхолостую и с -v: без -v rsync об удалениях молчит
rsync -az --delete -v --dry-run -e ssh \
  backend/public/ <адрес>:/opt/integram/backend/public/ | grep '^deleting '
```

Смотреть перечень глазами. Если в нём есть что-то, чего в локальном дереве нет по
замыслу, — **остановиться** и вынести это в `/opt/integram/shared/`, а не удалять.
Только после этого — настоящий прогон без `--dry-run`.

Перезапуска не требуется: nginx раздаёт файлы.

---

## Ручная выкладка портала

```bash
cd portal && npx nuxt build && cd ..
rsync -az --delete -v --dry-run -e ssh portal/.output/ <адрес>:/opt/integram/portal/.output/ \
  | grep '^deleting '
# посмотреть перечень, затем без --dry-run
ssh <адрес> 'pm2 restart portal'
```

`.output` пересобирается целиком, поэтому `--delete` тут обязателен. Перечень всё
равно смотреть: если каталога на сервере нет, удалять будет нечего, и это нормально;
если удаляется что-то постороннее — значит туда что-то положили руками.

## Сигнальный сервер звонков

**Скрипт выкладки его не знает.** Только вручную.

Это отдельная служба на Go: групповые звонки идут через неё, прямые звонки 1-1 —
через WebSocket самого бэкенда. Бинарник лежит в репозитории собранным, Go на
сервере не нужен.

```bash
# сборка нужна только если правился signal/ (нужен Go 1.21+)
bash signal/build.sh

# выкладка
scp signal/integram-signal-linux <адрес>:/opt/integram/integram-signal
ssh <адрес> 'pm2 restart signal'
ssh <адрес> 'curl -s http://127.0.0.1:8090/health'   # {"ok":true}
```

**Ключ подписи обязан совпадать с ключом бэкенда.** Сигналка проверяет токен,
который выдаёт бэкенд; разошлись ключи — групповые звонки молча перестают работать,
пользователь видит только «Ошибка сигнального сервера» и бесконечный реконнект.
Проверять так:

```bash
ssh <адрес> '
b=$(grep -m1 "^JWT_SECRET=" /opt/integram/backend/.env | cut -d= -f2-)
s=$(grep -m1 "INTEGRAM_JWT_SECRET=" /opt/integram/signal-start.sh | cut -d\" -f2)
[ "$b" = "$s" ] && echo СОВПАДАЮТ || echo РАЗНЫЕ'
```

Второе, что ломается молча, — список допустимых источников. Если стендов на машине
два, а в `ALLOWED_ORIGINS` записан один домен, второй получает отказ на апгрейде
соединения. Признак в журнале:

```bash
ssh <адрес> 'grep -c "origin not allowed" /root/.pm2/logs/signal-error.log'
```

Переменные читаются из `signal-start.sh` — правки в соседних файлах вида
`*.ecosystem.js` на процесс НЕ действуют, потому что PM2 запускает именно скрипт, а
тот перекрывает окружение своими `export`.

## Проверка после выкладки

**Код ответа `200` ничего не доказывает.** Заглушка одностраничного приложения
отвечает `200` на любой адрес, включая выдуманный. Проверять содержимым.

```bash
bash scripts/deploy-prod.sh health
```

Что смотреть в выводе:

| Строка | Что означает отказ |
|---|---|
| Расхождение с репозиторием | прод отдаёт не то, что в HEAD; разбирать `check-prod-drift.mjs` |
| Канал присутствия | журнал визитов не наполняется при живых визитах |
| Обязательные ключи `.env` | без них процесс поднимется, но работать не будет |
| Порты | пропавший порт = упавшая служба, которую PM2 показывает живой |

**Проверяя вручную — доказывай, что мерил своё.** На машине бывает несколько
бэкендов и несколько порталов. Замер обязан возвращать адрес вместе с числами;
ноль вместе с нулевой длиной ответа означает «страницы нет», а не «значений нет».

**Кэш врёт в обе стороны.** Серверная функция кодспейса отвечает прежней редакцией
ещё около сорока секунд; портальные компоненты живут в `localStorage` браузера и не
чистятся обычным обновлением страницы; артефакты раздаются с годовым
`Cache-Control: immutable`. Первый вердикт выносить только после того, как кэш
заведомо вытеснен, иначе проверяется не то, что выложили.

## Откат

Атомарных релизов нет: каталог на сервере один, симлинк не перевешивается. Откат —
это выкладка прошлого коммита.

```bash
# 1. Что стоит на проде и кто выкладывал последним
node scripts/check-prod-drift.mjs --host <адрес>
ssh <адрес> 'tail -20 /opt/integram/.deploy-journal.log'

# 2. Отдельное дерево на последнем исправном коммите.
#    Ветку НЕ переключать: в репозитории работают параллельные сессии
git worktree add .claude/worktrees/rollback <sha>
cd .claude/worktrees/rollback

# 3. Выложить и убедиться
DEPLOY_HOST=<адрес> bash scripts/deploy-prod.sh back
DEPLOY_HOST=<адрес> bash scripts/deploy-prod.sh health
```

**Чего откат не возвращает:**

- **Схему базы.** Обратных миграций нет. Откат кода оставит новую схему под старым
  кодом. Восстановление — из ежедневного дампа, с потерей всего, что записано после
  ночного снимка.
- **Отправленное наружу.** Вебхуки, письма, сообщения ботов уже ушли.
- **Пользовательские файлы.** Они вне выкладки — это верно и нужно, но означает, что
  рассинхрон «запись есть, файла нет» откатом не лечится.

Дерево отката не удалять до выяснения причины: из него же выкладывается исправление.

---

## Частые отказы и что они значат

| Что видно | Что произошло |
|---|---|
| `password authentication failed` после выкладки | перезаписан `.env`, либо в нём заданы `DATABASE_URL`/`DB_*` вместо `INTEGRAM_DB_*` — боевой путь читает только вторые |
| «холостой прогон не удался» | rsync не смог измерить удаления: сеть, ключ, права. Выкладка остановлена намеренно — пустой перечень неотличим от «удалять нечего» |
| «ввод закрыт — подтверждение получить неоткуда» | выкладка с `--delete` запущена неинтерактивно. Подтверждать удаления вслепую нельзя |
| «уже идёт выкладка» | замок занят другой выкладкой. Если она мертва — в сообщении будет номер процесса и команда снятия |
| «нет ключа: X» | в боевом `.env` не хватает обязательного ключа. Дописать на сервере, не в репозитории |
| Портал отдаёт старую разметку | `.output` не пересобран, либо в браузере живёт кэш скомпилированных компонентов |
| Библиотека портала пропала со всех порталов | снесены артефакты в `shared/`. Восстанавливать из журнала выкладки по контрольной сумме |
| PM2 показывает `online`, а служба не отвечает | процесс жив, но порт не слушается. Смотреть перечень портов, а не статус |

## Чего не делать никогда

- **`rsync --delete` по каталогу, где живёт что-то серверное.** Список того, что
  переживает выкладку, всегда длиннее, чем помнится.
- **`pm2 restart all`** на машине, где может быть сосед.
- **Править данные в боевой базе, когда ошибка в шаблоне или настройке.** Чинить
  источник и выкладывать заново.
- **`git stash` без путей.** Тайник общий на весь репозиторий и снимается из любого
  рабочего дерева — вытащишь чужой.
- **Обходить хук через `--no-verify`.** Хук либо нужен, либо его надо чинить.
- **Судить об успехе по коду ответа и по дате файла.** `rsync -a` переносит время
  источника: откатанный файл выглядит свежим. Сверять содержимым.
- **Удалять область на одном стенде, не проверив, куда он пишет файлы.** Если корень
  пользовательских файлов не задан явно, он вычисляется от расположения кода, и две
  установки рядом получают один и тот же каталог: удаление на одном уничтожает файлы
  одноимённой области на другом.
